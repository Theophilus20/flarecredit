Security & anti-gaming

A credit score is only useful if it can be trusted. That's why the enclave only counts verified activity when calculating your score.

AttackDefense
Attest someone else's transactionsA proof counts only if the payment was sent from your bound XRPL address, checked via the source address hash.
Forge or tamper with historyEvery proof is Merkle-verified against the on-chain FDC round root before scoring.
Resubmit one proof repeatedlyDeduplicated by transaction ID the same payment counts exactly once.
Pay yourself to farm volumeTransfers where sender and receiver match are discarded.
Ping-pong funds between two walletsVolume is capped at 100 XRP per counterparty, so wash trading saturates one cap instead of inflating the score.
Spin up a fresh walletWallet-age points require the oldest attested transaction to exceed 30 days.
Forge a score envelopeThe registry recovers the signature and accepts it only from the key whitelisted for that code hash; tampered signatures revert.
Run modified enclave codeReproducible builds mean a modified binary produces a different code hash, and its signatures are rejected.
Replay an identity signatureChallenges are domain-bound to the chain ID and registry address, with single-use nonces and a short TTL.

Known limitation. Preventing duplicate identities without compromising privacy is still an open challenge. We're evaluating approaches that improve uniqueness while keeping user data private.
